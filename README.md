# English Quick Answer — iPhone / GitHub Pages

英語の問題文と選択肢を音声または写真から読み取り、AIで回答する日本語UIのWebアプリです。**iPhone Safariでの利用を前提**に作成しました。ビルド不要で、フォルダの中身をGitHubにアップロードできます。

## 1. GitHub Pagesへ配置

最初の配置操作はPCで行うと簡単です。

1. ZIPを解凍し、`english-quick-answer` フォルダを開きます。
2. GitHubで「＋ → New repository」。名前を `english-quick-answer` などにし、Pagesを利用できる公開範囲で作成します。一般にはPublicが簡単です。
3. 「uploading an existing file」または「Add file → Upload files」。
4. **フォルダの中身**をすべてドラッグ＆ドロップ。`index.html` がリポジトリの一番上に来るようにします。外側のフォルダ自体を追加すると1階層深くなります。
5. 「Commit changes」。APIキーやパスワードをファイルに書き込まないでください。
6. 「Settings → Pages → Build and deployment」。Source を「Deploy from a branch」、Branch を「main」、Folder を「/ (root)」にして「Save」。
7. デプロイ後にPages欄に表示されるHTTPSのURLをコピーします。通常は `https://ユーザー名.github.io/リポジトリ名/` です。

GitHub Pagesは静的サイトを配信するサービスです。個人用の直接接続モードなら、この配置以外にサーバーの用意やnpm installは不要です。

## 2. iPhoneで初回設定

1. iPhoneの**SafariでPagesのHTTPS URL**を開きます。LINE等のアプリ内ブラウザではなくSafariを使ってください。
2. 「接続・設定」→「個人用：OpenAIへ直接接続」。自分のOpenAI APIキーを入力して「設定を適用」。
3. 「サンプルを入力」→「この問題に回答」で `B. goes` が返るか確認します。
4. 「音声入力方式」が「iPhone推奨：録音 → AI文字起こし」になっていることを確認します。
5. 「音声認識を開始」でマイク利用を許可し、問題文とすべての選択肢を読み上げます。

AI回答・録音文字起こしにはAPIの利用設定と料金が必要です。ChatGPTの有料契約とは別料金です。APIキーはコードに記載せず、画面から入力します。APIキーと接続パスワードはメモリ内だけで保持し、再読み込みで消えるため、再度入力してください。

ホーム画面から開きたい場合は、Safariの共有メニューから「ホーム画面に追加」。アイコンと単独画面表示を用意しています。追加後の初回起動ではAPIキー・マイク権限を再設定する場合があります。オンライン専用です。

## 3. UI1：音声から自動回答

### iPhone推奨：録音方式

1. 「01 音声で質問」を選択します。
2. 次の問題を始めるときは「新しい問題」を押します。
3. 「音声認識を開始」→問題文とすべての選択肢を話します。
4. 音声を検出した後に設定時間の無音が続くと、自動で録音停止→AI文字起こし→問題欄に表示→回答します。
5. 「停止して回答」を押して手動で送信することもできます。

SafariのMediaRecorderに対応するMP4/AACを優先します。録音中は途中の文字起こしは表示されません。録音方式はファイル完成後に文字起こしするため、リアルタイム認識より通信が1回増えます。確実な操作経路を優先したiPhone向けの初期設定です。

- 自動送信の無音待ち時間は初期1.8秒。選択肢の途中で止まる場合は3秒／5秒にするか、「無音後に自動回答」をオフにして停止ボタンを使います。
- 無音検出は端末の音量による簡易判定です。騒音や小声では判定が変わります。音声解析が動かない環境でも手動停止で送信できます。
- 1回の録音は最大60秒。長い問題は分けて追加録音できます。音声未検出が続く場合は約15秒で終了します（音声解析が有効な場合）。
- 言語は文字起こしモデルが判定します。「認識言語（ブラウザ）」欄は録音方式では無効です。
- 文字起こしを修正して「この問題に回答」も使えます。
- 録音時は画面を開いたままにしてください。画面ロック／別アプリへの移動で録音を破棄して停止します。

### 高速：ブラウザのリアルタイム認識

音声入力方式を切り替えると、ブラウザのSpeechRecognitionを使用します。途中結果を逐次表示し、確定した文字を問題欄へ反映します。確定結果更新後に設定時間待ち、未確定文字がなければ自動回答。これは認識イベントに基づく待機判定です。

録音アップロードの待ち時間を省けますが、iOS・ブラウザ・音声認識サービスの設定や通信状況に依存します。動かない場合は録音方式へ戻してください。認識がブラウザ側で終了した後は、再度開始ボタンを押します。未確定文字が残った場合は確認を促し、勝手に確定しません。

**どちらの方式もiPhoneのマイク入力が対象です。他アプリの動画・通話・iPhone内部音声を直接取り込む機能はありません。** 別端末からの再生音をマイクで拾う場合は、音量と周囲の騒音を調整してください。

## 4. UI2：左に写真、右に音声

1. 「02 写真 ＋ 音声」をタップします。
2. 左側で「写真を選択 / 撮影」、または「カメラを起動」→「この画面を撮影」。
3. 初期設定では写真選択後に自動で文字起こし＋回答。答えを先に表示し、続けて問題の文字起こしと理由を表示します。
4. 右側では同時に音声の問題を処理できます。

- **iPhoneの縦画面でも左右表示**です。読みにくい場合は「上下表示に切替」、またはiPhoneを横向きにします。
- UI1／UI2は上部のボタンで即時切替。入力と回答を保持します。写真の文脈を使う設定が切替で変わる場合だけ、処理中の音声回答・文字起こしを中止します。
- 写真パネルのカメラプレビューは音声なしで取得します。iOSのシステム撮影画面や写真選択に移るとページが一時停止する場合があるため、**写真を選んでから音声入力を開始する手順が確実**です。画像のAPI処理と音声のAPI処理は独立して並行できます。
- 問題と全選択肢が大きく、明るく写るように撮影してください。
- 「写真を選んだら文字起こし＋回答」をオフにしてから撮影し、「文字起こしのみ」を使うこともできます。
- 読み取り結果を修正し「修正文で回答」。この場合は修正テキストだけを送り、写真を再参照しません。
- 写真と音声が同じ問題なら、左の読み取り完了後、「左の問題文も音声の回答に使用する」をオンにして右で回答します。写真の文字起こしを再利用するため、画像を再送信しません。
- 画像読み取り中に、この連携回答を開始すると、読み取り完了を待つよう表示します。左右別々の回答にはこの制限はありません。

## 5. 高速化と計測

| 項目 | 初期値・方式 | 調整 |
|---|---|---|
| 音声入力 | iPhoneは録音方式 | 対応するSafariではリアルタイム認識も比較できます |
| 自動回答待機 | 1.8秒 | 1.2秒は速い一方、途中送信が増えます |
| 回答モデル | `gpt-4.1-mini` | 利用権限のあるResponses API画像対応モデルに変更可能 |
| 録音文字起こしモデル | `gpt-transcribe` | 利用可能な音声ファイル文字起こしモデルを指定 |
| 写真 | 長辺1600px、JPEG品質0.86 | 1280pxは軽量、2048pxは小さい文字用。変更後は再選択 |
| 写真解析 | OCR＋回答を1回の通信 | OCRと回答を別APIで順番に呼ぶ待ち時間を省略 |
| 回答表示 | ストリーミング | 全文完成前に回答が見えます |
| 回答量 | 答え＋短い理由 | 「答えのみ」で出力量を削減 |
| 並行処理 | 写真と音声を独立実行 | 同じ入力の自動回答重複を抑制 |
| 中断 | 問題変更で古い処理をキャンセル | 古い回答が新しい問題に混ざることを防止 |

回答に「最初の文字まで／完了まで」、録音文字起こしに処理秒数を表示します。回答時間には録音・認識待機・ファイル変換時間は含みません。写真ではマーカー受信と答えの可視化に少し差が出る場合があります。回線、モデルの混雑、画像内容に依存するため絶対的な応答秒数は保証できません。文字の読み取り精度と速度にはトレードオフがあります。

## 6. 共通APIキーを非公開にする場合

同梱の [worker/README.md](worker/README.md) を使うと、Cloudflare WorkerにOpenAI APIキーを保持し、iPhone側は中継用パスワードだけで接続できます。OpenAI APIキーを利用者へ渡したくない場合に使ってください。

GitHub Pagesだけではサーバーの秘密を保持できません。GitHub SecretsからJavaScriptに埋め込んだキーも、配信後は閲覧できます。初期設定は自分のiPhoneで自分のキーを入力する個人用です。

## 7. 保存と送信

- APIキー／中継パスワード：メモリ内のみ。設定適用後は入力欄も空にします。「認証情報を消去」でも削除できます。
- モデル、接続方法、Worker URL、画像サイズ、回答量：localStorageに保存。
- 音声・写真・問題・回答：アプリ独自の履歴保存は行いません。再読み込みすると消えます。
- 録音方式の音声はOpenAIへ送信。リアルタイム認識はブラウザの認識サービスへ送られる場合があります。
- 問題テキスト・写真はOpenAIへ送信。中継方式はCloudflare Workerを経由します。
- 回答APIは `store:false`。提供事業者側のすべてのログ・保持が無効になる意味ではありません。
- カメラは撮影後・UI1への切替・ページ非表示時に停止。マイクもページ非表示時に停止します。
- メモリ保持でも端末管理者やブラウザ拡張機能に秘密を隠すことはできません。共有利用では中継方式を選んでください。

## 8. トラブル対応

| 症状 | 確認 |
|---|---|
| Pagesが404 | mainブランチのrootにindex.htmlがあるか、Pages設定と公開状況を確認 |
| マイクが許可されない | Safariのサイト設定・iPhoneのマイク許可を確認。HTTPSのPages URLで開く |
| リアルタイム認識が動かない | 「iPhone推奨：録音 → AI文字起こし」に変更 |
| 録音が途中で送られる | 無音待ちを3～5秒にするか自動をオフにして手動停止 |
| 録音が送られない | 「停止して回答」。音量が小さい・周囲が騒がしい場合は自動判定が安定しないことがあります |
| 写真が開かない | JPEG / PNG / WebP / GIF、20MB以下を使用。HEICはJPEGへ変換。iPhoneの撮影設定で「互換性優先」も選択可能 |
| 文字が小さい／判読ミス | 問題だけ大きく撮影、反射を避ける、2048pxで再選択。文字欄を修正 |
| 401 | APIキー／中継パスワードを設定し直す |
| 429 | API残高、利用上限、混雑を確認 |
| 通信不可 | Wi-Fiやモバイル回線、社内プロキシ、OpenAI到達性、Worker URLとCORSを確認 |
| 中継が403 | ALLOWED_ORIGINは `https://ユーザー名.github.io`。リポジトリ名や末尾スラッシュを含めない |
| 回答が途中 | 問題が長い・出力上限・通信切断。短く分けて再実行。写真の全文文字起こしには上限があります |
| ホーム画面版で設定が消えた | メモリ内キーは再起動で消えます。APIキーを再入力 |

## 9. 同梱ファイルと検証

| ファイル | 役割 |
|---|---|
| `index.html` / `styles.css` | 日本語UI、iPhoneの左右／上下表示、16px入力、safe-area |
| `app.js` | モード切替、カメラ、画像縮小、音声入力、API処理 |
| `recorder.js` | MP4優先録音、簡易無音検出、録音時間制限 |
| `core.js` | API本文、SSE受信、写真の回答・文字起こし解析 |
| `manifest.webmanifest` / `icon.png` | ホーム画面への追加用設定 |
| `worker/` | 任意の中継サーバー、導入手順 |
| `docs/DESIGN.md` | 詳細設計と検証状況 |
| `tests/` | ロジック・DOM／メディア／APIを模した操作テスト |

開発者向けテスト（Node.js 20以上、追加パッケージ不要）：

```bash
npm test
```

PCでのローカル表示（Pythonあり）：

```bash
python3 -m http.server 8000
```

PCでは `http://localhost:8000` で開けます。iPhoneからHTTPのPCのIPアドレスを開く方法ではマイク・カメラが制限されるため、iPhoneの確認にはHTTPSのPages公開URLを使ってください。index.htmlのダブルクリック（file://）では利用しません。

自動テストはモック環境での検証です。**Safariの描画・iPhone実機のマイク／カメラ・実際のAPI応答速度は未検証です。** 公開後は次の順に実機確認してください。

1. サンプル問題の正解が `B. goes`。
2. 音声録音→停止→文字起こし→回答。
3. 音声の無音停止。途中で切れたら待ち時間を調整。
4. 写真撮影→問題欄と回答。
5. UI2の左右表示／上下表示、UI1への切替で入力が維持されること。
6. 写真の解析中に音声を入力し、両方の結果が表示されること。
7. ホーム画面に追加して再度マイク・カメラを確認。

生成AIの回答と文字起こしの正確さは保証されません。問題文と選択肢を確認して使用してください。
